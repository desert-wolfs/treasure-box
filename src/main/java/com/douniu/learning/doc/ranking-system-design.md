# 排行榜系统设计终极版（亿级数据 + 秒级访问 + 冷热数据架构）

## 一、背景

排行榜系统广泛存在于互联网产品中，例如：

-   游戏战力排行榜
-   点赞排行榜
-   财富排行榜
-   活跃度排行榜
-   直播打赏榜

在大型互联网平台中，排行榜系统往往需要支持：

  指标       规模
  ---------- -------------
  用户规模   10亿
  日活用户   1亿
  查询QPS    10万\~100万
  查询延迟   \< 20ms

系统需要解决以下核心问题：

1.  如何支持 **亿级数据排序**
2.  如何实现 **秒级查询**
3.  如何设计 **冷热数据分离**
4.  如何避免 **全量排序**
5.  如何防止 **刷榜作弊**
6.  如何处理 **热点Key问题**

------------------------------------------------------------------------

# 二、排行榜访问特点

真实系统中排行榜访问分布极不均衡。

假设排行榜有 10 亿用户：

  排名范围   访问占比
  ---------- ----------
  Top100     70%
  Top1000    20%
  Top10万    9%
  其他用户   1%

因此：

> 绝大多数用户只关心排行榜前列。

这就是冷热数据划分的核心依据。

------------------------------------------------------------------------

# 三、冷热数据划分

排行榜中的冷热数据不是根据更新时间判断，而是根据以下三个维度。

## 1 排名区间

  排名范围    数据类型
  ----------- ----------
  Top100      热
  Top1000     热
  Top10万     温
  100万以后   冷

## 2 访问频率

系统会统计访问次数，例如：

user_rank_access_count

如果：

access_count \> threshold

则认为是热数据。

## 3 是否影响榜单

如果某用户有可能进入 Top 榜单，系统会优先放入热存储。

------------------------------------------------------------------------

# 四、排行榜分层存储

大厂通常采用分层存储结构：

Client\
↓\
Redis (Top1万 / Top100万)\
↓ miss\
DB / HBase

数据分层如下：

  排名范围   存储
  ---------- ---------------
  Top1万     Redis
  Top100万   Redis Cluster
  其余用户   HBase / MySQL

优势：

90%请求命中 Redis。

------------------------------------------------------------------------

# 五、排行榜分片设计

假设排行榜有 10 亿用户。

为了避免单机瓶颈，需要进行分片。

分片数量：

1024 shards

每个 shard：

约 100 万用户

计算方式：

shard = userId % 1024

数据结构示例：

rank:shard:1\
rank:shard:2\
rank:shard:3

------------------------------------------------------------------------

# 六、TopK优化

排行榜通常只需要前列数据，例如：

Top100\
Top1000\
Top10000

因此可以使用 **TopK算法**。

每个 shard 只维护：

Top1000

例如：

Shard1 Top1000\
Shard2 Top1000\
Shard3 Top1000

总数据量：

1024 × 1000 = 102万

然后进行合并排序得到：

Global Top1000

------------------------------------------------------------------------

# 八、冷热数据迁移

系统会定期执行后台任务：

RankScanner

执行周期：

每 5 分钟

逻辑：

扫描排行榜变化

如果用户：

掉出 Top10万

执行：

Redis → DB

如果用户：

进入 Top10万

执行：

DB → Redis

冷热数据是动态变化的。

------------------------------------------------------------------------

------------------------------------------------------------------------

# 十、防刷榜设计

排行榜系统必须防止作弊。

常见策略：

### 1 行为检测

例如：

1 秒内增加 100 万积分

系统会标记异常。

### 2 风控系统

检测：

-   IP
-   设备ID
-   用户行为轨迹

异常行为会被限制。

### 3 延迟入榜

积分变化后不会立即进入排行榜。

流程：

用户积分变化\
↓\
进入缓冲区\
↓\
风控检测\
↓\
更新排行榜

------------------------------------------------------------------------

# 十一、热点Key问题

例如：

rank:top10

可能被访问：

100万 QPS

解决方案：

### 1 多副本Key

rank:top10:1\
rank:top10:2\
rank:top10:3

随机读取。

### 2 本地缓存

服务端使用 Local Cache（如 Guava Cache）。

### 3 CDN缓存

Top10榜单可以缓存到 CDN。

# 十三、总结

亿级排行榜系统核心思想：

1 分片存储\
2 TopK计算\
3 冷热数据分离\
4 多级缓存\
5 风控防刷榜
