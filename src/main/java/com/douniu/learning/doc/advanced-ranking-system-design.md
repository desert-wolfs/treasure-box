# 大厂级排行榜系统设计（10亿用户架构）

## 1. 系统背景

排行榜系统常见于： - 游戏战力榜 - 点赞榜 - 财富榜 - 活跃榜 - 直播打赏榜

目标规模： - 用户：10亿 - DAU：1亿 - 查询QPS：10万\~100万 -
查询延迟：\<20ms

核心问题： 1. 亿级数据排序 2. 秒级查询 3. 冷热数据分离 4. 防止刷榜 5.
解决热点Key

------------------------------------------------------------------------

## 2. 排行榜访问特点

访问高度集中在头部：

  排名      访问占比
  --------- ----------
  Top100    70%
  Top1000   20%
  Top10万   9%
  其余      1%

结论： \> 绝大多数请求集中在排行榜前列。

------------------------------------------------------------------------

## 3. 冷热数据划分

判断依据：

1.  排名位置
2.  访问频率
3.  是否影响榜单

  数据类型   示例
  ---------- ----------
  热数据     Top100
  温数据     Top10万
  冷数据     长尾用户

------------------------------------------------------------------------

## 4. 分层存储架构

Client ↓ Redis（Top1万） ↓ Redis Cluster（Top100万） ↓ HBase / MySQL

优势： 90%请求直接命中Redis。

------------------------------------------------------------------------

## 5. 分片设计

用户规模：10亿

分片数量：1024

计算方式：

shard = userId % 1024

每个 shard ≈ 100万用户

------------------------------------------------------------------------

## 6. TopK优化

每个 shard 仅维护：

Top1000

总数据量：

1024 × 1000 ≈ 102万

再合并生成：

Global Top1000

避免全量排序。

------------------------------------------------------------------------

## 7. 查询流程

Top榜查询

Client → Redis → 返回结果

用户排名查询

Client → Redis → miss → DB/HBase

------------------------------------------------------------------------

## 8. 多级缓存

Client ↓ CDN ↓ Gateway ↓ Local Cache ↓ Redis ↓ Database

------------------------------------------------------------------------

## 9. 防刷榜设计

策略：

-   行为检测
-   风控系统
-   延迟入榜

流程：

积分变化 → 风控 → 更新排行榜

------------------------------------------------------------------------

## 10. Hot Key问题

例如：

rank:top10

可能 100万QPS

解决方案：

1.  Key多副本
2.  本地缓存
3.  CDN缓存

------------------------------------------------------------------------

## 11. 实时排行榜计算

使用流计算：

Kafka → Flink → Redis

实时计算 TopK。

------------------------------------------------------------------------

## 12. 完整系统架构

User ↓ API Gateway ↓ Score Service ↓ Kafka ↓ Flink Rank Compute ↓ Shard
Redis ↓ Global Rank ↓ Cache/CDN

------------------------------------------------------------------------

## 13. 总结

核心原则：

-   分片
-   TopK
-   冷热分离
-   多级缓存
-   风控防作弊

一句话总结：

只实时维护少量关键排名数据，其余通过分片和冷热分离处理。
